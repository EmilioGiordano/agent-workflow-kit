### The loop
```
TASK -> implementer (own worktree) -> reviewer -> FAIL? -> same implementer fixes -> same reviewer re-reviews
                                              PASS -> merge main -> gate -> push -> PR -> CI -> UI validation -> merge
```

### Who does what
| Action | Orchestrator | Implementer | Reviewer | User |
|---|---|---|---|---|
| Write TASKs, create branches and worktrees | yes | no | no | — |
| Commit on its branch | yes | yes | no | — |
| Push a branch, open a PR | yes | no | no | — |
| Merge a PR that meets the merge policy | <yes \| no> | no | no | yes |
| Push to `main`, force-push, delete branches or worktrees | never | never | never | yes |

Anything not listed is not permitted by default.

### Branches and worktrees
- One branch per topic: `<type>/<topic>`, English. Types: `feat`, `fix`, `improve`, `refactor`, `perf`, `test`, `chore`, `build`, `docs`, `spike`.
- One branch, one worktree, one implementer. Two branches that touch the same files never run in parallel.
- `TASK-*.md`, `REPORT*.md` and `.build-slot` are untracked (gitignored).
